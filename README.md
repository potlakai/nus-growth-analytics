# Nūs Growth Analytics

A BI model of the real download and funnel data of [Nūs](https://github.com/potlakai/nus-desktop), a desktop app I built and launched.

- **Raw data:** GitHub release-download snapshots taken every 4 hours, site analytics, and product funnel events.
- **Pipeline:** sanitized CSVs → a star schema → SQL analysis → statistics → dashboard.
- **Portable SQL:** the same SQL runs locally in DuckDB and on Amazon Athena over S3 (`sql/athena/`).

## Business questions

1. Where do downloads come from (product, platform, release)?
2. How fast does a release's pull decay? That decides how often shipping a release is worth it.
3. Where does the site funnel lose people?
4. Did paid promotion beat organic?

## Model

```
                 dim_date (date_key, full_date, week_start, iso_day_of_week, is_weekend)
                    |
dim_asset ---- fact_downloads_daily ---- dim_release
(release file:   (date, asset, release: cumulative and     (repo, tag, published_date)
 product, kind,   daily downloads, days since release)
 platform)
                 fact_site_daily (date, page: hits) ---- dim_page
                 fact_funnel_daily (date, event: count)
```

**Grain decisions** (each one came from a bug the data exposed):

- **Facts are per release file per day, not per file name.** `Nus-Setup.exe` ships in several releases. Deltas taken by file name alone mixed releases and went negative.
- **The asset dimension is keyed by repo + tag + file.** The same file name was `legacy` in early releases and `full` later. Keying on the name joined twice and double-counted.
- **Daily downloads = the cumulative count at the day's last snapshot minus the previous day's, via `LAG`.** An asset's first day is `NULL` (unknown), never 0.

## Findings (from `docs/results.md`, regenerated by `analysis/run.py`)

| Question | Answer |
|---|---|
| Where downloads come from | 170 new installer downloads in the 14-day window: the full app on Windows 49%, Companion on Windows 45%, macOS 6%. Of 408 lifetime downloads, v0.2.6 (213) and Companion v0.1.0 (115) account for 80%. |
| Release decay | Average daily downloads per release file: 1.77 in a release's first week, 0.99 in weeks 2-3, 0.01 after. OLS of daily downloads on log(1 + days since release), controlling for product, with robust errors: coefficient **-1.28, p < 0.001** (n = 326). Distribution is release-driven, so release cadence is a growth lever. |
| Site funnel | landing view 34 → download click 9 (26%) → install 8 → app open 8 → first ask 6 → sign-in 3. The biggest drop is landing to download click. |
| Paid vs organic (X campaign) | Profile-visit rate: organic 1.61% vs paid 0.29%, 5.5x. Chi-square = 37.3, p < 0.001. |
| Weekday vs weekend | No difference (Welch t-test p = 0.86). |

## Data quality notes

- **Site visits read 0 before 2026-10-06, when analytics tracking went live.** Those zeros are missing data, not zero traffic. Only 3 tracked days overlap the download data, so the traffic-to-downloads regression waits for 30+ tracked days.
- **The paid vs organic numbers come from X's analytics panel, which is internally inconsistent** (organic expands > total on one post). Treat that test as directional.
- **Small samples:** 14 days of snapshots and a funnel with tens of users. The findings show direction and method, not precise effect sizes.

## Run it

```
python -m venv .venv && .venv/Scripts/pip install duckdb pandas statsmodels scipy matplotlib tabulate
python extract.py growth.db  # growth.db -> data/raw/*.csv (query strings stripped: they carry signed tokens)
python analysis/run.py       # star schema -> data/model/*.csv, queries + stats -> docs/results.md, charts -> docs/
```

AWS: `docs/AWS-STEPS.md` covers S3, Athena (`sql/athena/00_external_tables.sql`, then `sql/model/star_schema.sql` unchanged) and a QuickSight dashboard.
